Offline device queue

Replay log from POS devices (client_mutation_id). API: POST /api/v1/pos/offline-sync/ and batch.

When sync shows 409 catalog_stale

The device sent a menu fingerprint (payload.catalog_version) that no longer matches the server outlet catalog (prices, items, promos, etc. changed). The API rejects the mutation and records a failed row here so you can see it.

  • On the POS: refresh the cached catalog (same source as GET /api/v1/pos/catalog-version/?outlet=…), then replay the same client_mutation_id with the updated fingerprint.
  • Batch sync: the failing entry returns ok: false and status_code: 409 for that index only; other operations may still apply.
  • The Server (now) column below is the fingerprint at page load—use it to confirm the device is behind after menu edits.
